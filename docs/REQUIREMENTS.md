# TunLatch 需求文档

状态：已有只读观察器、离线工具和部分领域模型，PF 执行与真实防泄漏保护尚未实现；当前能力与边界以 [README](../README.md) 为准。2026-11-02 按用户决定转向代理 UID 兼容模式（见 §3.3），该方向尚未生效。完整开发计划、实验记录和证据属于本地未跟踪资料，不在本仓库发布。

相关文档：[技术栈调研与选型建议](TECH-STACK-RESEARCH.md)、[Rust 代码规范与实践指导](CODING-GUIDELINES.md)。

## 1. 背景与目标

目标设备使用 v2rayN 的 TUN 模式代理。代理客户端、代理内核或 TUN 转发出现异常，以及系统路由发生变化时，流量可能回退为直连，向目的站点暴露设备的真实出口 IP。

TunLatch 是独立于代理客户端运行的 macOS 本地防火墙，使用系统自带 PF 为整机出站连接提供兜底保护，通过终端交互界面（TUI）管理。

核心目标：保护启用后，普通流量通过选定的可信代理 TUN；物理出口仅允许已批准代理 socket UID 的 TCP/UDP，以及独立批准的最小系统例外，其他未授权直连保持阻断。当前选择 UID 0，以兼容 v2rayN 的规则模式直连；它不承诺所有目的站点都看不到本机真实出口。旧的“仅节点目标白名单、全部业务强制入隧道”不再作为本次交付目标。

## 2. 当前范围与技术约束

- 当前仅供个人自用，优先满足用户当前 Mac 和 v2rayN TUN 环境。
- 保护范围为整机出站连接，包括局域网访问；不新增入站限制。
- 全部自研程序代码使用 Rust，覆盖 TUI、后台服务、规则管理、系统集成及安装卸载逻辑。PF 规则、launchd 配置等使用系统要求的配置格式。
- 使用 macOS 系统自带 PF，不依赖 Network Extension、付费开发者账号或关闭 SIP/AMFI。
- 项目独立实现，不以 `vpn-kill-switch/killswitch` 作为直接改造基底；允许参考公开实现，优先复用成熟 Rust 组件和系统能力，不重复造轮子。
- 当前不实现按可执行文件/PID/签名控制、代理协议或代理客户端，不要求 GUI、DMG、商店上架或对外分发。socket UID 授权是账户级例外，不是应用身份隔离。
- 具体 TUI 库、持久化方案和内部架构由设计文档与实现决定；SQLite 可按需采用，不作为强制依赖。

## 3. 出口保护策略

### 3.1 保护底线

- 持续限制实际出口，不依赖检测到代理崩溃后才临时封网。
- 代理退出、转发失效、TUN 消失、路由变化或流量转向其他网卡时，未授权直连必须受到阻止。
- 代理进程存活、网卡存在、网卡名称以 `utun` 开头或默认路由指向 TUN，均不能单独作为保护有效的依据。
- 保护同时覆盖新连接和已有连接，避免 PF 状态表中的旧状态绕过新的出口约束。
- 普通出站规则中的“允许”不能自行产生物理出口授权；物理放行必须另有有效 UID 授权或最小系统例外。普通规则的显式阻止也约束这些例外。

### 3.2 TUN 发现与绑定

- 自动发现可能用于代理的 TUN，展示足够的信息供用户确认和选择。
- 只信任选定的代理 TUN，不自动放行其他 VPN、系统服务或软件创建的虚拟网卡。
- IPv4、IPv6 及双栈 TUN 均需纳入处理，不能因没有 IPv4 地址而忽略网卡。
- 支持多个虚拟网卡并存；可信身份不能仅依赖固定网卡编号或点对点标志。
- 代理重启导致 TUN 重建或编号变化后，能够确认属于同一代理时自动重新绑定；身份不明确时保持阻断，并提供手动确认途径。
- 旧网卡编号被其他隧道复用时，不应自动继承信任。

### 3.3 代理 UID 出口授权与必要系统例外

- 保留可信 TUN 授权；在明确批准的物理链路上，独立允许本地 socket 的有效创建 UID 等于批准代理 UID 的 TCP/UDP。当前用户选择 UID 0，链路观察样本为 en0；数字 UID 与实际物理范围必须进入受保护的管理员策略，不能硬编码成所有环境的默认放行。
- UID 授权可承载代理外层和规则模式直连，无逐个业务/节点目标和端口白名单要求；不将提供过的实际上游 IP/端口写入代码或默认配置。节点地址在同一 UID/协议/链路/地址族授权范围内变化，不需要重新批准每个 IP；范围变化仍需管理员，不临时全面放行。
- 按 socket UID 匹配不证明仅来自 sing-box。当前用户接受符合条件的其他 root socket 也能直连；root 本可修改 PF/系统，属于既定信任边界。root 创建后降权或交给其他进程的 socket 凭据也须实测说明。不能宣称“仅代理进程直连”或“所有业务始终隐藏出口”。
- PF 查询不能解析 socket UID、转发/无 owner、其他 UID、其他协议或未批准出口不得命中该 UID 放行；禁止把 unknown 当 root、以 group/wheel 代替或未限定协议地生成 user 放行。
- DHCP客户端、IPv6邻居发现及必要组维护、相关ICMP错误采用已确认的最小双栈设计，具体包条件须由管理员批准的最小例外策略冻结。不能默认放行全部 DNS、广播、组播或局域网访问。
- ICMP/ND 等不能依赖 user 限制的流量，及 DHCP 等可能无 socket owner 的系统流，另按必要目标/协议/端口/type/code/链路制定最小例外。未在当前最小集合中明确列出的条件不启用。root TCP/UDP DNS 可被同一 UID 授权允许，不能由此承诺加密或远端 DNS。
- UID 授权和系统例外均独立、明确、可见；导入普通规则不生成批准，增删/收窄/换代按权限 A 需要管理员，且处理旧连接。其他 root 风险的接受不豁免其他 UID、持续 TUN 身份、状态、共存和系统覆盖验证。

## 4. 生命周期与恢复

- 退出 TUI、关闭终端或控制进程异常后，已经生效的保护继续保留，不因界面退出而自动解除。
- 只有用户显式停用保护才解除本项目施加的限制；卸载过程中如需解除，也须让用户明确知晓。
- 保存保护启停状态。Mac 重启后自动恢复上次状态；此前开启时，在可信 TUN 就绪前保持阻断，仅保留已确认的必要例外。
- 重启恢复须尽早建立阻断规则，开机保护的实际生效时点及可能的启动空窗需验证并说明。
- 规则或配置更新失败时，保留原有有效保护或进入阻断状态，不临时开放直连。
- 支持后台运行和重新连接 TUI。状态无法确认、后台异常或 PF 被外部停用时，明确报告实际状态，不能继续显示保护有效。
- 提供安装、状态恢复、卸载和本机终端解除限制的方法，解除操作不依赖外网可用。

## 5. TUI 与规则管理

- 通过 TUI 完成 TUN 选择、保护启停、规则编辑、必要例外管理和状态查看，支持清晰的键盘操作与结果反馈。
- 展示当前可信 TUN、保护是否实际生效、是否正在阻断、规则命中信息及异常原因。区分用户期望的启用状态与系统实际生效状态。
- 显示需要管理员权限的操作及授权结果，不将授权失败、规则加载失败或未知状态呈现为成功。
- 出站规则支持文件导入、导出和 TUI 内编辑，使用一致的数据模型与匹配语义。
- 规则支持目标 IP/网段、端口、协议等常用过滤条件，以及明确的允许、阻止和优先级语义。统一规则管理以满足实际需求为限，不预设复杂 DSL 或通用插件系统。
- 导入和编辑需校验配置，并给出可理解的错误说明；无效或不完整配置不能覆盖当前有效配置。

## 6. PF 集成要求

- 与系统及其他软件的 PF 规则共存，仅管理本项目所需的规则和配置变更；不能把清空全局规则或全部连接状态作为常规启停流程。
- 正确处理规则优先级、实际执行位置、连接状态及接口约束，不能只以配置文件写入成功作为保护生效依据。
- 对已有连接的必要处理应确保保护有效，并控制对其他连接和网络功能的影响。
- 停用和卸载仅撤销本项目的变更，不关闭其他软件仍在使用的 PF 功能，也不移除其规则。
- 特权操作和配置输入须受到约束，不能把导入内容作为任意命令执行。

## 7. 验收与交付

防泄漏验证覆盖 IPv4/IPv6、TCP/UDP（含 QUIC）、DNS、新连接和已有连接，至少包含以下场景：

| 场景 | 预期结果 |
| --- | --- |
| 可信 TUN 正常工作、v2rayN 规则模式 | 应用流进入可信 TUN；批准 UID 可在批准物理口产生代理外层和规则直连；其他 UID 的非例外物理流阻断 |
| 同 UID 的独立 root 程序 | 同条件 TCP/UDP 可通，明确记录为接受的账户级范围，不宣称仅代理可通 |
| unknown UID、非 TCP/UDP、未批准出口 | 不命中 UID 放行；只有独立批准的系统例外可通 |
| 多个 TUN 并存或旧编号被复用 | 其他网卡不因名称或类型相似而获得信任 |
| 代理退出、TUN 消失或转发失效 | 未授权直连被阻止，必要例外范围不扩大 |
| 代理重启、TUN 重建或编号变化 | 确认同一代理后自动恢复，否则继续阻断 |
| 路由变化、网络切换、睡眠唤醒 | 出口约束持续成立，不因旧连接或状态迁移绕过 |
| TUI 退出、控制进程异常或配置更新失败 | 保护不被自动解除，恢复后状态显示真实 |
| 重启前保护已开启 | 自动恢复保护，可信 TUN 就绪前维持阻断 |
| 显式停用或卸载 | 撤销本项目限制，保留其他 PF 配置与规则 |
| 撤销/改变 UID 授权、收窄物理范围或普通 block | 新旧 TCP/UDP 均不继续利用旧授权；无关状态影响可核查 |

验证以实际出口、物理网卡抓包或其他可核查证据为准，不能只检查程序输出、配置文本或网页显示的单个 IP。系统代发流量、必要例外及启动阶段的覆盖边界需明确记录。

后续交付包括可构建运行的 Rust 项目、必要的自动化检查与实机验证记录，以及可重复的构建、安装、使用、恢复和卸载说明。最低 macOS 版本、处理器支持范围及具体例外策略需在后续设计与实机验证中确定；本文件不预设内部实现架构，也不代表这些能力已被验证。
